# 1. CORE PURPOSE

KNOW HOW is an **Automotive Cybersecurity Document Knowledge and Guidance Platform**.

The application helps cybersecurity engineers understand:

- What each document section contains
- What needs to be updated
- What information is required
- Who owns the activity
- What checklist should be followed
- What the latest reference input looks like
- How to understand unfamiliar sections
- How to ask questions about any cybersecurity document

The application uses three primary sources:

```text
Template DOCX
      ↓
Main Document UI

knowledge.xlsx
      ↓
Section Guidance / Update Information

Reference-image/
      ↓
Visual Reference Input
```

The future AI assistant will provide additional cybersecurity guidance.

---

The application has the following input files/folders.

## FILE 1 — TEMPLATE DOCUMENT

Example:


# 48. MOST IMPORTANT ARCHITECTURAL RULE

The application has four independent information layers:

```text
┌─────────────────────────────────────────┐
│              KNOW HOW                   │
├─────────────────────────────────────────┤
│                                         │
│  TEMPLATE DOCX                          │
│  "What does the official document       │
│   look like?"                           │
│                                         │
│  knowledge.xlsx                         │
│  "What guidance/update information      │
│   is available?"                        │
│                                         │
│  Reference-image/                       │
│  "What does the reference input         │
│   look like?"                           │
│                                         │
│  AI Assistant                           │
│  "How can I understand/update it?"     │
│                                         │
└─────────────────────────────────────────┘
```

The source responsibilities are:

```text
DOCX
→ Main document appearance/content

knowledge.xlsx
→ Guidance and update information

Reference-image/
→ Visual reference examples

AI
→ Future contextual assistance
```

Do not mix these sources.

# 49. FINAL PRODUCT EXPECTATION

The final KNOW HOW application must feel like a **real enterprise automotive cybersecurity engineering platform**.

It should not feel like:

- An Excel viewer
- A Word converter
- A simple document reader
- A generic admin dashboard
- A prototype

It should feel like:

> **An intelligent cybersecurity engineering workspace where the official document, engineering guidance, reference examples, and future AI assistance are connected through a single professional interface.**

The visual experience should be:

**Accurate + Professional + Futuristic + Enterprise + Easy to Use**

Most importantly:

> **Preserve the original template document visually and structurally while adding KNOW HOW's interactive intelligence around it.**

Before implementing the final UI, inspect the actual input files and use their real structure rather than assuming the examples above are the exact document structure.

Do not invent missing content.

Do not replace document content with placeholder text when the real input exists.

Do not remove tables or formatting to simplify implementation.

Build the application around the actual contents of the supplied files.
